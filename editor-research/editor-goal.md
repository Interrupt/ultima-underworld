# Goal for /goal: finish the editor master plan

Work through everything in `editor-research/editor-master-plan.md` that is not yet built, on branch `underworld-editor`. Read the plan first and keep it current: when something is built or a decision changes, update the plan in the same commit (including its open questions). You are done when every item below is implemented, works in the running editor, and is covered by a test or an ASan regression demo.

Standing rules: one batch of work at a time; after each batch run ctest, `zig build` and `./run-regressions.sh` (all `CLEAN 0`; note the known intermittent `demo_summon_flood` crash in `settle_dropped_object` is not an editor bug), then commit and push, and send a screenshot of the progress. Mark deviations from the original with `// HACK: not original behaviour`. Add every new source file to both `CMakeLists.txt` and `build.zig`, and stub new globals and functions in the extraction-based test fixtures. Regression demos must never write into the repo's `data/` directory: give each isolated run its own copy of `DATA\LEV.ARK`.

1. Master archive. The editor reads and writes the master `DATA\LEV.ARK`, not save slots. Entering the editor reloads the current level from it; Save writes the current level into it (keep a one-time `LEV.ARK.BAK` of the pristine file); Play saves, copies `DATA\LEV.ARK` over `SAVE0\LEV.ARK`, then leaves the editor and drops the player at the camera's position and facing. Remove the `LEV_EDIT.ARK` export. Add a parameterised level loader (a `load_level_from_archive`) rather than touching the game's stairs path.
2. Safety layer: arena-snapshot undo and redo (arena, scheduler table, texture map; a ring of snapshots, one per operation or stroke) with Ctrl+Z / Ctrl+Y, and a dirty flag with an unsaved marker in the status bar.
3. Escape menu: a popup over the editor with Save, Revert (always confirms), Change level (Page Up / Page Down, clears selection and Mv, camera to an open tile), Play and Exit; a Save / Discard / Cancel prompt when dirty. Escape first cancels a pending Move or Copy.
4. Object mode: the Back button; Replace with brush (warns across the static/mobile boundary); the Comm page as type-level COMOBJ properties and the Class page as type-level OBJECTS.DAT data (both labelled as game-wide), with the creature instance fields on their own page; selecting a palette type opens its Comm and Class pages; trap and trigger parameter pages with Set Target (select a trigger, click a tile); editor markers that draw invisible objects, traps and triggers as clickable icons, with a view toggle (the eye button); Move and Copy into containers.
5. Map pane: the camera's view cone, and a zoom.
6. Mode buttons: wire the mode column so each button switches the editor's panels and palette (object, tile properties, texture painter, view options, Find, cut/copy, paste, paint bucket), and mark the active one.
7. Picking: a tile-index pick buffer so 3D clicks on walls and floors report a tile and a face.
8. Tile and terrain mode: tile type and height brushes, scope, door and no-magic flags, the readout, eyedropper, rectangle paint, raise and lower, map coloured by height, and the consistency checks after each stroke.
9. Texture painter: this level's wall and floor slot palettes with usage counts, slot editing versus tile painting, the ceiling picker, unmapped-texture handling, and the rebuild of the texture caches; confirm the slot counts and where the ceiling texture is stored.
10. Fill tool: flood fill with the paint targets and spread rules in the plan, stopping at doors by default, with a hover preview and rectangle fill.
11. Find: recover the dead find-next routine (name it, add it to the function database, pin its behaviour with a unit test), wire Find Next and Previous to the camera, the criteria (type, category, owner, whoami, what links to this, trigger target, flags), a results list, and the validation searches.
12. Cut, copy and paste of tile regions (tiles only: type, height, flags and both texture slots), with the consistency checks run on the destination.
13. Later: replace the fullscreen boolean with a viewport struct read at the roughly eight viewport sites, so the 3D pane can match the original's aspect without cropping.

Testing: Unity unit tests for every mutation asserting the object-list validator and free counts, with undo restoring state byte for byte (including deleting a multi-object tile head, nested containers, class-7 scheduler objects, a full free list, fills across doors and platforms, and slot edits); and `demos/demo_editor*.txt` regression scripts under ASan covering each tool. Finish by resolving or documenting each open question in the plan.
